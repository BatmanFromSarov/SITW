## 2. Миссия проекта

SITW (Something In The Way) — бесплатный, настраиваемый, автономный офлайн ИИ-помощник, предназначенный для поддержки людей в тяжёлые периоды жизни, в том числе при выгорании.

Главный ориентир проекта:

**Если SITW поможет хотя бы одному человеку справиться с выгоранием, это уже победа.**

SITW не должен заменять человеческую поддержку или профессиональную помощь.

Девиз проекта:

«Даже среди всей этой тьмы — я вижу свет».

## 5. Результаты аудита старого прототипа

Старый прототип содержит несколько несовместимых предположений о структуре базы данных и функциях модулей.

Обнаружены следующие проблемы:

- Несогласованные схемы таблицы `users`.
- Отсутствующие функции и поля, на которые ссылаются отдельные модули.
- Зависимость Telegram-прототипа от внешнего ИИ-сервиса.
- Небезопасная зависимость игровых наград от текста ответа языковой модели.
- Демонстрационная запись о выгорании, создаваемая при запуске логирующего модуля.
- Необходимость отдельно проверить два пути запуска onboarding.

Предварительная проверка синтаксиса Python прошла для семи файлов. Проверка целостности старой базы SQLite вернула `ok`, но это не подтверждает корректность всей архитектуры.

Старые исходники и база данных должны сохраняться до создания резервных копий и принятия отдельного решения об их использовании.

**Не переносить старую реализацию в новое ядро без проверки совместимости.**

## 6. Текущая цель

Главная ближайшая задача — реализовать первый технический этап SITW v0.1: надёжное ядро с консольным интерфейсом, базовым циклом диалога, сохранением истории в SQLite, восстановлением после перезапуска, обработкой ошибок и автоматизированными тестами.

Для проверки Core, CLI и SQLite допускается временный тестовый адаптер ответов. Он не является локальным ИИ и не подтверждает интеграцию языковой модели.

Приоритетный порядок:

1. Определить структуру проекта и границы модулей.
2. Создать минимальное запускаемое приложение.
3. Реализовать консольный интерфейс и базовый цикл диалога.
4. Реализовать сохранение истории в SQLite.
5. Проверить восстановление истории после перезапуска.
6. Добавить обработку ошибок и базовые тесты.

После завершения и проверки первого технического этапа утверждена последовательность:

1. Интеграция локального ИИ.
2. Расширенная долговременная память и управление контекстом.
3. Адаптивное поддерживающее взаимодействие.

Осмысленный диалог с локальной моделью, расширенная память и адаптация остаются обязательными направлениями развития SITW, но не являются условиями завершения первого технического этапа v0.1.

Workshop, RPG, голосовые функции и сложная персонализация относятся к будущим этапам.

**Файлы:** `app.py` — CLI; `sitw/core/assistant.py` — единственный класс тестового `Assistant`; `sitw/core/__init__.py` — реэкспорт; `sitw/database/storage.py` — SQLite; `tests/test_storage.py` и `tests/test_cli.py` — тесты.

**Поведение:** SQLite создаётся в `data/sitw.db` относительно корня проекта; `data/` создаётся автоматически, файлы БД исключены из Git. Повторная инициализация не удаляет сообщения. История читается по `id ASC`; при запуске выводится количество восстановленных сообщений, но тестовый ответ не зависит от истории.

**Частичный отказ:** если запись пользователя прошла, а запись ответа не удалась, пользовательская запись остаётся. CLI сообщает об ошибке и завершает работу. Ответ не регенерируется автоматически.

**Проверки:** выполнить `python -m unittest discover -s tests -v` и `python app.py` на целевой машине. Результаты отдельного локального запуска должны быть подтверждены в отчёте, а не выводиться из наличия тестов.

**Ограничения:** нет Local AI, расширенной памяти, адаптации; интеграция с актуальным GitHub не проверена. Следующий шаг — сверка файлов и контрольная проверка на машине владельца; не расширять архитектуру без отдельного согласования с владельцем проекта.

## Историческая контрольная точка — 01.11.2026 (отдельный адаптер Ollama)

По прямому запросу владельца реализован отдельный адаптер этапа 2 — Local AI.
Утверждённая архитектура, Конституция и философия не изменены.

**Реализовано:**

- `sitw/core/ollama_backend.py`: `OllamaBackend`, структурно совместимый с `TextBackend`.
- Запрос `POST http://127.0.0.1:11434/api/generate` через стандартный `http.client`;
  модель по умолчанию `qwen2.5:7b`, `stream: false`, только текущее сообщение.
- Модель и тайм-аут задаются в конструкторе; тайм-аут по умолчанию 120 секунд.
- Ошибки транспорта, HTTP и поля `error` преобразуются в `GenerationError`;
  некорректный JSON/UTF-8, пустые, нетекстовые и незавершённые ответы — в
  `InvalidResponseError`. Технические подробности не включаются в текст ошибок.
- HTTP-ответ и соединение закрываются при завершении запроса, в том числе при
  ошибках. Повторный `close()` безопасен и запрещает дальнейшую генерацию;
  он не останавливает сервер и не выгружает модель из Ollama.
- `tests/test_ollama_backend.py`: 11 тестов с подставными HTTP-ответами,
  включая совместимость с `Assistant`, отсутствие истории и управление ресурсами.

**Проверено:** `python -m unittest discover -s tests -v` — 34/34 успешно
(23 существующих и 11 новых). В песочнице Windows запуск `python.exe` был
недоступен; та же команда успешно выполнена вне песочницы после разрешения.
Автоматические тесты не обращаются к реальному Ollama; тесты SQLite используют
временные базы. Пользовательская база и `.bak`-файлы не изменялись.
`git diff --check` выполнен успешно; новые файлы дополнительно проверены через
`git diff --no-index --check` — ошибок пробелов нет.

**Ограничения:** CLI продолжает использовать `TestBackend`; адаптер не подключён
к `app.py`. Реальный Ollama и модель не запускались и не проверялись.
Производительность, качество ответов, требования к памяти и автономность
на целевом компьютере не подтверждены. Тайм-аут ограничивает отдельные операции
сокета, а не полную длительность генерации. Запрос синхронный, без повторов;
история и системные инструкции SITW не передаются.

**Следующий шаг (не реализован):** отдельно подключить выбор backend в CLI,
передавать `OllamaBackend` в `Assistant` с сохранением текущей обработки ошибок
и жизненного цикла. Перед реальной проверкой потребуется запущенный локальный
Ollama с установленной `qwen2.5:7b`; проверить успешный диалог, отказы, сохранность
истории и работу без интернета. Этап 2 целиком не завершён.

**Запуск:**

```text
python app.py

python app.py --backend ollama --model qwen2.5:7b --timeout 120
```

По умолчанию используется прежний `TestBackend`. Модель по умолчанию —
`qwen2.5:7b`, тайм-аут — 120 секунд. Допускается дробный положительный конечный

до открытия SQLite. `--model` и `--timeout` применяются только к Ollama;
в тестовом режиме корректные значения принимаются, но не используются.
`--help` выводит параметры без открытия ресурсов.

**Проверено автоматически:** `python -m unittest discover -s tests -v` —
40/40 успешно (34 существующих и 6 новых тестов). Python недоступен внутри
песочницы Windows; команда успешно выполнена вне песочницы через разрешение
инструмента. `git diff --check` — без ошибок.

Новые тесты проверяют выбор backend, значения параметров, справку, ошибки
аргументов, полный путь CLI → Assistant → OllamaBackend с mock HTTP,
успешное сохранение ответа и восстановление истории. Во время mock-запроса
проверяется, что пользователь уже записан в SQLite. Отказ соединения,
тайм-аут, HTTP-ошибка, некорректный JSON, поле `error` и пустой ответ сохраняют
пользователя без ложного ответа assistant и без технических подробностей
в сообщении CLI. Проверяется закрытие HTTP и SQLite; существующие тесты
проверяют закрытие backend, в том числе при ошибках и прерывании ввода.
Использованы только временные базы; реальная генерация не выполнялась.

**Ограничения и риски:** реальный сервер Ollama, наличие модели, совместимость
оборудования, скорость, качество, потребление памяти и автономность не проверены.
Генерация синхронная, без автоматических повторов. Тайм-аут ограничивает
операции сокета, а не полную длительность ответа. История восстанавливается

## Актуальная контрольная точка — 02.11.2026 (контекст Ollama)

Рабочая ветка: `feature/ollama-dialogue-context`. По утверждённому плану
реализована передача сохранённой истории SQLite в `POST /api/chat`.
Предыдущие сведения о передаче только текущего текста являются историческими.

**Реализация:** CLI сохраняет пользователя, затем читает последние N записей
по `id` в хронологическом порядке. `--context-messages N` задаёт положительный
целый лимит (по умолчанию 40), включая текущее сообщение. После выбора окна
Core исключает только ведущие `assistant`, для которых пользователь остался
за его пределами. Незавершённые `user`, в том числе последовательные, остаются.
История уже содержит текущее сообщение: оно не добавляется повторно; одинаковые
тексты разных сообщений не объединяются. SQLite при чтении не изменяется.

Добавлен необязательный протокол `ChatBackend.generate_chat(messages)`;
`TextBackend.generate(message)`, старые backend и `TestBackend` совместимы.
`OllamaBackend.generate(message)` отправляет одно сообщение через тот же chat API.
В запрос включаются только `role` и `content`, модель и `stream: false`.
Ответ принимается только с `message.role: assistant`, непустым строковым
`message.content` и `done: true`. Ошибки HTTP/транспорта/API и некорректные
ответы обрабатываются безопасно, HTTP-ресурсы закрываются. При сбое CLI
оставляет пользователя без фиктивного ответа и завершается без повторов.

**Запуск:** `python app.py --backend ollama --context-messages 40`.
В тестовом режиме корректный параметр лимита принимается, но не используется.

**Изменённые файлы:** `app.py`, `sitw/core/backend.py`,
`sitw/core/assistant.py`, `sitw/core/ollama_backend.py`,
`sitw/database/storage.py`, четыре файла `tests/test_*.py`,
`SITW_HANDOFF.md`, `SITW_ROADMAP.md`.

**Проверено:** `python -m unittest discover -s tests -v` — 46/46 успешно;
`git diff --check` — без ошибок. Python запускался вне песочницы с разрешением,

**Ограничения:** лимит измеряется сообщениями, а не токенами; длинный текст
может превысить окно модели. При запуске для прежнего уведомления о количестве

Тайм-аут ограничивает операции сокета, а не полную длительность ответа.
Реальный Ollama, скорость, качество, память и автономность не проверены;
